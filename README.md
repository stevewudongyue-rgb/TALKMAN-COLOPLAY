# TALKMAN COLOPLAY

**说话输入，在电脑上编辑，用 COLOPLAY 操作，确认后填入 Agent。**

配合初代 COLOPLAY 的独立桌面客户端：电脑负责文字编辑，设备旋钮、四个按键和圆屏负责操作与提醒。没有设备时也能使用桌面按钮和设置中的模拟器。

开发测试版 **0.1.28.67**：按 Desktop 0.1.41 的行为适配输入位置记忆。右下＋旋转预选 Agent，松开即选定；桌面选择目标也不再强制弹出位置选择。默认优先明确的主输入框，本次运行中分别记住已确认的窗口／对话位置。窗口拖动无需重选；临时填空由桌面“选择输入位置”主动指定，原控件失效时停止填入并提示重选。不会按旧坐标猜测，也不恢复旧发送确认。主动指定的位置仅保留在本次运行，重启后需重新确认；Desktop 0.1.42 的点击红框界面尚未适配。沿用65卡带，其屏幕可能仍写“松开后选位置”，实际行为以桌面为准；包含66 USB测试修复。USB卡屏、真实Agent与Mac原生验收仍待验证，尚未进入一键升级。下文64的“每次选位”属于旧发布行为。

开发中 0.1.28.65／卡带65：有 CXUS v2 的新固件时，桌面优先通过 USB 同步画面和按键，设置中的 Wi-Fi 折叠为备用；设置 → 语音可选电脑或 COLOPLAY 麦克风。设备麦克风音频经 USB 传给桌面，再沿用现有语音服务识别。Windows 已完成协议、模拟设备及编译检查；新固件真机录音和 Mac 成品尚待验收，**当前一键升级仍是64，不能用它取得USB新版**。现有62卡带的 Wi-Fi 连接继续使用；65客户端与65卡带需配套安装。设备固件只支持旧图流时不会启用设备麦克风。

## 后续发布流程

每次交付的新版本在 Windows、Mac 相关回归和成品检查通过后，同步发布到应用内一键升级。使用 `TalkMan-发布工具/TalkMan-发布一键升级.py`：本地包和清单核对 → 上传安装包 → 客户端实际下载并校验 → 备份旧清单并原子切换 → 验证旧版能发现更新、新版不重复提示。升级说明必须写明是否需要更新设备卡带，配对 ROM 由各电脑导出。发布完成后把线上版本与验证写入现有研究记录。

### Mac 构建交接：优先公司 M2

后续默认把已提交源码通过 GitHub 同步到公司 M2，在原生 arm64 桌面会话构建；只有 M2 不可用时，才手动触发 GitHub Actions 的 Mac 工作流。源码推送不再自动启动云端编译。同一提交已有通过验收的产物时直接复用，避免重复编译。

公司 M2 使用 macOS 14 及以上、python.org 的 Python 3.12／3.13（含 Tk），首次用 `xcode-select --install` 安装命令行工具；在终端确认 `python3 -c 'import platform; print(platform.machine())'` 输出 `arm64`。使用独立源码目录，不把它覆盖到 Applications 或用户配置目录。

构建65及以上时先运行 `brew install opus`。构建脚本会检查 arm64 架构，并把 Opus 解码库复制进应用；成品验收会从 DMG 加载该库。用户安装应用后不需要 Homebrew。

首次获取源码：

```bash
git clone --branch codex/coloplay-display-51 https://github.com/stevewudongyue-rgb/TALKMAN-COLOPLAY.git TalkMan-COLOPLAY-source
cd TalkMan-COLOPLAY-source
```

后续先 `git status --short` 核对本地改动；工作树干净时 `git pull --ff-only`。有改动先保留并核对，不使用强制重置。用 `git rev-parse HEAD` 记录待验收提交，然后依次执行（前一步失败即停）：

```bash
python3 TalkMan-构建Mac.py --test-dmg &&
bash TalkMan-Mac回归.command &&
TalkMan-venv-mac/bin/python TalkMan-Mac成品验收.py
```

从 `dist-mac` 交付 DMG、应用 ZIP、`TalkMan-SHA256SUMS.txt`、`TalkMan-Mac验收.json`，同时记录源码提交和回归日志。回归使用隔离数据与模拟模型；成品验收关闭在线服务。仍须在目标 M2 手测系统授权、真实录音、Agent 填入及设备连接，这些不能由离线通过代替。测试包未完成 Apple 公证；沿用既有一键升级发布流程，验收通过后再发布，不修改本机 Key、草稿或配对。

## 开始使用

1. Windows 运行安装器；Mac 打开 DMG，把 **TALKMAN COLOPLAY.app 拖到 Applications**，再从“应用程序”打开。均无需 Python。
   已安装的旧版需要先手动升级到 .52；以后可在 **设置底部 → 一键升级** 检查并安装新版。
2. 新安装默认使用**免费语音识别与星辰文字改写**，无需 API Key。点击“录音和覆盖”开始，再点停止；选中文字时覆盖选区。
3. “指令修改”按口述要求修改文字；AI 改写可先检查再确认。
4. 选择目标 Agent，先填入输入框，核对后再发送。

Mac 首次连接设备允许“本地网络”，录音允许麦克风，填入 Agent 时开启辅助功能。此 DMG 是未公证测试版；若系统阻止，尝试打开后到 **系统设置 → 隐私与安全性 → 仍要打开**，无需关闭系统安全保护。Intel Mac 暂不支持。

联网时，主动录制的音频及待处理文字会发给在线服务。免费服务使用 SenseVoiceSmall 和星辰 Xing4.0-29B，受额度及服务策略限制。推荐长期使用者在 **设置 → 模型连接** 填入自己的千问 API Key，再关闭免费服务；按自己的账户计费。

## Mac 首次使用引导

首次打开会在主窗口内显示六步引导：**安装位置 → 麦克风 → 语音服务 → 设备连接 → Agent 授权 → 开始使用**。

- 直接申请麦克风授权、打开对应系统设置；返回后自动检查实际状态。引导不会自动录音。
- 默认免费语音和星辰改写，也可进入模型设置填写自己的千问 Key；保留已有服务选择与凭证。
- 设备页直接刷新 Mac IP、填写可选设备 IP、保存并连接。引导会区分模拟器与真实连接；本地网络是否授权需在系统设置查看。
- 辅助功能用于填入其他应用；只编辑或复制文字可以跳过。设备不在手边也能先使用桌面程序。
- “稍后继续”保留步骤。在 **设置 → 新手引导** 继续，最后可查看四键与旋钮图解，再进入正文试录。

三键更新手势从 **61 卡带**起支持；首次配对请安装当前62版配对卡带。首次新电脑配对仍需安装对应卡带，引导不绕过系统授权，也不把源码导出当作已安装。

## 换网络，只在桌面改地址

**先升级一次客户端与新版配对卡带，之后同一台电脑换网无需重新编译或安装卡带。**

1. 电脑和 COLOPLAY 加入可互通的局域网，保留 USB 数据线用于实体按键。
2. 在 **设置 → COLOPLAY → 设备连接** 启用服务和“自动寻找已配对电脑”。
3. 点击“本机 IP”旁的**刷新**，选择这台电脑的当前地址，再保存。
4. “设备 IP”通常留空；网络限制广播时，填入 COLOPLAY 当前 IP 后保存。

本机 IP 是电脑地址，设备 IP 是 COLOPLAY 地址，两者不要填反。若填写了设备 IP，换网后也要更新它。macOS 提示“本地网络”时允许；网络隔离或防火墙仍可能阻止连接。

新版设备会寻找持有原配对信息的电脑，忽略其它未配对电脑。已有连接不会被发现广播打断。关闭自动寻找可继续使用原固定地址方式。

旧卡带没有发现能力，首次必须更新。通用安装包不含个人配对口令；“首次配对 · 导出源码”导出的是源码，首次配对仍需用开发工具编译为 ROM。换到另一台未配对电脑也需重新配对。ROM 使用固定短文件名 `TalkMan_COLOPLAY.rom`，勿增加点分版本号。

沿用 .46 的 Wi-Fi 心跳恢复修复及断线日志。纯 USB 图流另需设备固件支持 airimg。免费模型服务与设备连接相互独立。

应用内升级只替换程序，不迁移或删除用户数据。Windows 设置与草稿在 `%LOCALAPPDATA%\TalkMan-COLOPLAY`，Mac 在 `~/Library/Application Support/TalkMan-COLOPLAY`，Mac Key 存系统钥匙串。测试版未使用 Developer ID 签名，新版首次访问钥匙串、麦克风或辅助功能时，macOS 仍可能要求重新授权；数据并未因此清空。
